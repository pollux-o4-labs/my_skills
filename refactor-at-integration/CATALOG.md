# 기법 카탈로그

이름 있는 변환만 쓴다. 카탈로그의 기법은 동작 보존 절차가 정의되어 있어, 적용 후 무엇을 검증할지가 이름에서 나온다.

## 코드 기법

| 기법 | 적용 시점 |
|---|---|
| Extract Method | 주석으로 설명해야 하는 코드 덩어리. 함수가 한 화면을 초과 |
| Extract Class | 한 클래스가 변경 이유를 둘 이상 가짐 |
| Inline Method | 본문이 이름만큼 명확해 간접층이 값을 내지 못함 |
| Move Method / Field | 자기 클래스보다 다른 객체의 데이터를 더 사용 |
| Rename | 이름이 실제 동작과 불일치. 비용이 낮고 효과가 큼 |
| Replace Temp with Query | 임시 변수가 계산을 가려 추출을 방해 |
| Introduce Parameter Object | 같은 인자 묶음이 여러 함수에 되풀이됨 |
| Replace Conditional with Polymorphism | 같은 분기 조건이 여러 곳에 분산됨 |
| Remove Dead Code | 호출부가 0. 주석 처리로 남기지 않는다 — 이력이 정본이다 |

## 문서 기법

부연은 조문이 소유한다. 여기서는 이름과 적용 시점만 정한다.

| 기법 | 대응 코드 기법 | 적용 시점 | 조문 |
|---|---|---|---|
| 분할 | Extract Class | 한 문서가 주제를 둘 이상 안음 | 문서 저작 5 |
| 병합 | Inline Method | 문서가 상위를 가리키기만 함 | — |
| 이관 | Move | 평평한 디렉터리에서 스코프가 겹침 | 토픽 폴더 1 |
| 개명 | Rename | 같은 것을 두 이름으로 부름 | 어휘 층위 1 |
| 준용 전환 | Extract Method | 같은 규범이 두 곳에 원문으로 있음 | 문서 저작 2 |
| 지시 전환 | Replace Temp with Query | 개수·호출처·좌표를 사람이 적음 | 문서 저작 3 |
| 색인화 | — | 폴더가 무엇을 담는지 드러나지 않음 | 토픽 폴더 1 |
| 압축 | — | 예산 초과. 줄 나눔·이동은 압축이 아님. 유일본은 삭제 금지 | 문서 저작 5 |

이관·분할은 참조 갱신을 수반한다. 도구가 있으면 손으로 고치지 않는다.

## 코드 스멜

리팩토링이 필요하다는 신호이며 그 자체가 결함은 아니다.

- Duplicated Code · Long Method · Large Class · Long Parameter List
- Data Clumps — 같은 인자 묶음이 여러 곳에 되풀이됨
- Feature Envy — 자기 데이터보다 다른 객체의 데이터를 더 사용
- Shotgun Surgery — 한 변경이 여러 파일에 분산 적용됨
- Divergent Change — 한 파일이 서로 다른 이유로 수정됨

## 문서 스멜

| 스멜 | 대응 코드 스멜 | 무엇인가 |
|---|---|---|
| 정본 분열 | Duplicated Code | 같은 사실이 두 곳에 원문으로 있음 |
| 혼재 | Divergent Change | 한 문서가 서로 다른 이유로 수정됨 |
| 산재 | Shotgun Surgery | 한 주제가 여러 문서에 분산됨 |
| 전재 | — | 기계가 재계산하는 사실을 사람이 옮겨 적음 |
| 사문 | Dead Code | 참조도 갱신도 받지 않음 |

정본 분열이 가장 무겁다. 사본을 읽은 자가 그것을 정본으로 알고 작업을 이어 가며, 그 오류는 사본 쪽에서 관측되지 않는다.

## 정정 대상

스멜이 아니라 결함이다. 고치면 문서가 전달하는 내용이 바뀌므로 리팩토링과 커밋을 나눈다.

| 대상 | 무엇인가 |
|---|---|
| 낡음 | 코드·결정이 바뀌었는데 문서·주석이 그대로임 |
| 자기모순 | 한 문서가 다른 자리에서 어긋나는 말을 함 |
| 못 지킬 약속 | 검사가 재는 척하지만 실제로 재지 못하는 것 |

## 설계 원칙

- DRY — 같은 지식이 두 곳에 있으면 하나가 낡는다. 우연한 중복은 대상이 아니다
- SRP — 변경 이유가 하나여야 한다. 쪼개는 방향을 이것이 정한다
- OCP — 확장에 열리고 수정에 닫힌다. 단 활성 사례가 없는 확장 지점은 과잉이다
- 의존성 역전 — 구체가 아니라 추상에 의존한다. 결합도를 낮추는 주된 수단
- Deep Module — 인터페이스가 구현보다 단순해야 한다. 얕은 모듈 여럿은 큰 모듈 하나보다 불리하다

## 테스트

| 종류 | 역할 |
|---|---|
| 유닛 테스트 | 리팩토링의 안전망. 없으면 착수하지 않는다 |
| 특성화 테스트 | 시험이 없는 코드에 먼저 작성. 현재 동작을 결함까지 포함해 고정 |
| 회귀 테스트 | 적용 후 동작이 같음을 단언. 등가성 검증의 본체 |
| 뮤테이션 테스트 | 시험이 실제로 검출하는지 확인. 합격 판정 로직에만 사용 |

분기 커버리지는 변경분만 측정한다. 전역 목표를 두면 수치 충족이 목적이 된다.
