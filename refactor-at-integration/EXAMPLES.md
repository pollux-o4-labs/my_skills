# 적용 예시

스멜에서 기법으로, 기법에서 커밋 분할로 이어지는 실제 경로다.

## 예시 1 — 정본 분열

```
관측   두 조문이 같은 규범(중계 시 검증 의무)을 각자 원문으로 담음
스멜   정본 분열
기법   준용 전환 — 한쪽을 정본으로 지목하고 나머지는 링크
커밋   리팩토링 1건. 규범 자체는 바뀌지 않음
검증   두 조문의 요구가 이전과 같은지 대조
```

## 예시 2 — 전재

```
관측   명단 문서가 좌석 이름·차원·소유를 표로 나열
       세 열 모두 디렉터리 조회와 정의 파일에서 나옴
       실제로 한 좌석의 차원이 이미 어긋나 있었음
스멜   전재
기법   지시 전환 — 표를 제거하고 정본 디렉터리를 가리킴
커밋   리팩토링 1건. 판정 기준만 남기고 값은 제거
검증   문서가 주장하던 사실을 도구가 그대로 산출하는지 확인
```

## 예시 3 — 리팩토링과 정정이 함께 나온 경우

```
관측   채택 문서의 게이트 목록에 신설 서브커맨드가 빠짐        → 낡음
       같은 목록이 설정값 두 건도 누락                         → 낡음
       주석이 존재하지 않는 상수 이름을 가리킴                 → 낡음
       한 조문이 자기 배포물을 금지                            → 자기모순
       docstring 이 실재하지 않는 백스톱을 단정                → 못 지킬 약속

분류   전부 정정 대상. 리팩토링 아님
커밋   정정 커밋으로 분리. 같은 PR 의 리팩토링 커밋과 섞지 않음
검증   무엇이 바뀌었는지를 적는다. 등가성 검증은 성립하지 않음
```

## 예시 4 — 산재

```
관측   scripts/ 15건이 평평하고 공용과 저장소 고유가 섞임
       무엇이 공용인지 판정하려고 8개 파일을 전부 읽어야 했음
스멜   산재
기법   이관 — 토픽 폴더로 분류하고 색인화
주의   조문은 토픽이 갈리기 전에는 평평하게 두어도 된다고 정한다
       개수가 아니라 스코프 겹침이 판정 기준이다
커밋   이관과 참조 갱신을 한 커밋에 담는다. 끊긴 참조가 남으면 안 된다
```

## 예시 5 — 규모가 대형인 경우

```
관측   게이트 core 를 형제 저장소로 이관. 세 갈래가 서로 다른 파일을 건드림
판정   대형 — 공유 접합부를 건드림
분할   교차 결정(설정 오버레이 이름·경계)을 먼저 혼자 확정
       레인 3개를 파일 소유로 나눔
       감독이 정합성 소유자
검증   레인마다 감독이 직접 재현
       적대검증 3축이 반려 → 수리 → 재검증
커밋   관심사별 3건
```
